# v0.3.0 점검 결과

변경: 워크플로가 설치만으로 항상 켜지던 구조를 사용자가 부를 때만 켜지는 `/subagent` 스킬로 전환, L2 직접 경로 제거
원본 JSON: `data/v0.3.0/`, 실행 도구와 기준: [EVAL_DESIGN.md](EVAL_DESIGN.md)
조건별 1회씩의 동작 점검이며 효용 평가가 아님, v0.2.0 평가 결과([EVAL_RESULTS_v0.2.0.md](EVAL_RESULTS_v0.2.0.md))와 합산하지 않음
비용은 Claude Code CLI가 결과에 보고한 환산 값(`total_cost_usd`)이며 직접 계산한 금액이 아님, 구독 로그인이면 청구액이 아닌 사용 한도 소모

| 조건 | 호출처 파손 | 위임 | 비용 |

| Full (`/subagent`) | 0 / 호출처 6 | backend·architecture·backend·test·qa | 0.606달러 |

- 두 실행 모두 L3 절차(기획 파일, architecture-agent 조사, QA)를 따랐고 직접 수정으로 건너뛴 사례는 없었음
- v0.2.0에서 관찰된 L3 우회가 사라졌다고 결론내릴 수 없음(2회, 조건별 1회)

## 한계

- 반복 1회, 한 모델, 작은 합성 fixture, 비대화형 실행
- 대화형 화면(스킬 실행 허용 창, 신뢰 화면)은 확인하지 못함
- 워크플로가 직접 처리보다 낫다는 비교는 이번에도 수행하지 않음(직접 처리 기준선은 v0.2.0 측정값)
- 엄격 모드는 메인 세션의 모든 수정에 적용되는 설계가 바뀌지 않았음, 평소 대화에도 영향을 줄 수 있어 워크플로 실행 중으로 한정하는 개선이 남음
