## 해석과 한계

1. 어려운 과제 두 가지에서 direct보다 lite가 놓치는 요구와 깨뜨리는 호출처가 적었음. 이 범위에서는 설계가 기대한 방향
2. 표본이 과제당 3회이고 direct의 결과가 3회 모두 같아(분산 0) 같은 약점이 반복되는 것으로 보이나, 통계적 유의성은 주장하지 않음
3. 단일 소형 fixture와 단일 모델 결과라 다른 프로젝트와 모델에 일반화할 수 없음
4. 비용은 구독 로그인의 환산 값이며 청구액이 아님
5. 비대화형 실행이라 사용자 확인 단계가 없음. 설계 문서에 적은 대로 암묵 요구 결과 해석에 반영해야 함
6. 직접 처리가 이미 만점이던 과제는 이번 범위에 없어서 "워크플로가 쓸모없는 경우"의 비용 비교는 시범의 s1·x1(약 2배) 1회 값뿐임
7. 이전 측정(v0.2.0)에서 같은 과제 재측정 결과가 갈린 적이 있어 이 결과도 반복 확인이 필요함
