사용자에게 선택 항목 `phone`을 추가했습니다. `npm test`는 종료 코드 0이었고, 기존 테스트와 새 테스트 합쳐 12개가 통과했습니다. 별도 QA 검증도 R1~R4 모두 통과했습니다. QA는 테스트를 다시 돌리지 않고 기록만 확인했습니다.

| 항목 | 결과 |
| --- | --- |
| R1 `makeUser`가 `phone`을 받고, 값이 있을 때만 유지 | 충족 |
| R2 API 응답에 `phone` 키는 값이 있을 때만 포함, 없으면 키 자체가 없음 | 충족 |
| R3 화면 카드는 `이름 <이메일> · 전화번호`, 없으면 `이름 <이메일>` 그대로 | 충족 |
| R4 CSV 끝에 전화번호 열, 없으면 빈 칸 (예: `1,Ann,a@x.io,`) | 충족 |

**바뀐 파일**
- `src/users.js`
- `src/api/user-api.js`
- `src/ui/user-card.js`
- `src/export/user-export.js`
- `test/user-phone.test.js` (새 파일, 8개 테스트)

`dist/`, `config/`, 기존 테스트는 건드리지 않았습니다.

**안전한 쪽으로 판단한 내용**
- `phone`이 `undefined`, `null`, 빈 문자열이면 "없음"으로 처리했습니다. 그래서 빈 `phone` 키나 어색한 ` · `가 생기지 않습니다.
- CSV는 기존처럼 이스케이프하지 않습니다. 전화번호에 쉼표가 들어가면 열이 어긋날 수 있으니, 전화번호에 쉼표가 없다고 가정했습니다.
- 전화번호 형식 검증은 요청에 없어서 넣지 않았습니다.
- `phone`이 없어도 CSV는 항상 4열이라, 기존 사용자의 CSV 줄 끝에도 쉼표가 하나 붙습니다. 요청하신 동작입니다.
- `scripts/export-csv.js`는 상품 CSV라서 건드리지 않았습니다.

**확인 방식**
- 계획 확정은 제가 직접 했습니다(`confirmedBy: pm-agent`). 사용자 승인이 필요한 항목은 없다고 판단했습니다.
- 요구사항 문서 대조(`trace`)와 변경 기록 검증(`verify`)도 모두 이상 없음으로 나왔습니다.
- 화면 카드는 순수 문자열 함수라 테스트로만 확인했고, 브라우저로 화면을 열어 보지는 않았습니다.
- 커밋은 하지 않았습니다.
