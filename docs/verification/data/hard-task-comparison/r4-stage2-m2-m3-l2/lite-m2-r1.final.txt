discount 테스트가 통과합니다. `npm test`는 5개 모두 통과했고, 종료 코드는 0입니다.

**원인**: `src/discount.js`의 `percentOff`가 `Math.floor`로 소수점 이하를 버리고 있었습니다. 그래서 19.99에 10%를 할인하면 17.991이 17로 잘렸고, 테스트가 기대한 17.99가 나오지 않았습니다.

**수정**: `Math.round(total * (100 - pct)) / 100`으로 바꿨습니다. 결과를 소수 둘째 자리(센트)까지 반올림합니다. 바뀐 파일은 `src/discount.js` 하나뿐입니다. 테스트, `dist/`, `config/`는 건드리지 않았습니다.

**확인한 내용**
- 이 워크플로의 변경 등급은 L2로 분류했습니다.
- 확인은 `npm test` 실행 기록, 변경 diff 비교, 요구사항 추적 검사(trace)를 모두 통과했습니다. 별도 QA 에이전트의 최종 검증도 통과였습니다.
- `percentOff`는 이 파일과 테스트에서만 쓰입니다. 다른 호출부가 없어서 영향 범위는 작습니다.

**자동 실행이라 제가 대신 판단한 내용**
- 테스트 기대값(17.99)은 그대로 두고 소스만 고쳤습니다. 기존 테스트를 약화하지 않는다는 CLAUDE.md 규칙 때문입니다.
- 반올림 방식은 가장 가까운 센트로 반올림(Math.round)으로 정했습니다. 사용자 확인이 필요한 정책 결정일 수 있지만, 안전한 기본값으로 보고 진행했습니다.
- 계획은 사용자 확인 없이 PM이 직접 확정했습니다(`confirmedBy: pm-agent`). 사용자 승인이 필요한 항목이 없다고 판단했기 때문입니다.

**검증하지 못한 부분**
- 소수 셋째 자리 이상의 입력, 소수 할인율, 음수 금액은 반올림 경계에서 결과가 달라질 수 있습니다. 테스트와 호출부에는 이런 경우가 없어서 확인하지 않았습니다.
- `Math.round` 동작은 Context7이 등록되어 있지 않아 외부 문서로 확인하지 못했습니다.
