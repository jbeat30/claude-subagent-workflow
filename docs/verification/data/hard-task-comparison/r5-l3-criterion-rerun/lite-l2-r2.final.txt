사용자에게 선택 항목 `phone`을 추가했습니다. `npm test`는 13개 모두 통과했고, 그중 9개는 이번에 새로 만든 테스트입니다. 기존 테스트는 수정하지 않았습니다.

| 요구 | 결과 |
|---|---|
| `makeUser`가 `phone`을 받음 | 값이 있을 때만 `phone` 키를 넣습니다. |
| API 응답 | 값이 있으면 `phone` 키가 들어가고, 없으면 키 자체가 없습니다. |
| 화면 카드 | 값이 있으면 `이름 <이메일> · 전화번호`, 없으면 기존 그대로 `이름 <이메일>`입니다. |
| CSV | 끝에 전화번호 열이 붙고, 없으면 `1,Ann,a@x.io,`처럼 빈 칸입니다. |

수정한 파일은 `src/users.js`, `src/api/user-api.js`, `src/export/user-export.js`, `src/ui/user-card.js`이고, 새 테스트는 `test/user-phone.test.js`입니다. `dist/`와 `config/`는 건드리지 않았습니다.

**질문에 답할 수 없어서 안전한 쪽으로 판단한 것**
- **빈 값 처리:** `phone`이 빈 문자열이나 `null`이면 "없음"으로 취급했습니다.
- **CSV 이스케이프:** 전화번호에 쉼표가 있어도 처리하지 않습니다. 기존 CSV에도 이스케이프가 없어서 범위에서 뺐습니다.
- **형식 검증:** 전화번호 형식 검증은 요청에 없어서 넣지 않았습니다.
- **카드와 응답의 미세한 차이:** 카드는 값이 있으면 문자열이 아니어도 표시하고, API와 CSV는 문자열일 때만 처리합니다. 실제로는 차이가 나지 않는다고 QA가 봤습니다.

**워크플로 관련**
- 이 작업은 모델, API, 카드, CSV에 걸쳐서 L3로 분류했습니다. L3는 원래 사용자와 대화로 확인해야 하는데, 이번에는 그럴 수 없어서 제가 대신 확정했습니다.
- planner-agent는 부르지 않고 제가 직접 요구사항을 정리했습니다. 호출 막는 장치가 architecture-agent 보고서를 먼저 요구해서 그것은 호출했고, 그 뒤 개발과 최종 QA를 진행했습니다.
- QA 결과는 "요구 4개 모두 충족"입니다. QA는 점검 기록이 변조되지 않았는지는 확인하지 못했습니다.
- 이 저장소 밖에서 API나 CSV를 쓰는 곳이 있는지는 확인하지 못했습니다. CSV 열이 하나 늘었으니 외부에서 쓰는 곳이 있다면 확인해 주세요.
- 변경 사항은 커밋하지 않았습니다.
