# 어려운 과제 비교: 직접 처리 대 워크플로

무엇을 재는가: 같은 요청을 직접 처리했을 때와 `/subagent` 워크플로(Lite, 일부 Full)로 처리했을 때 결과가 어떻게 다른지
어려운 과제란 숨은 호출처, 말하지 않은 요구, 여러 영역에 걸친 변경처럼 직접 처리가 놓치기 쉬운 과제
설계와 성공 기준은 [평가 설계](../EVAL_DESIGN.md), 실행 방법은 [검사 방법](../TESTING.md), 실행 도구는 `tools/eval/hard/`
측정 환경은 모두 비대화형 실행(`claude -p`), 한 모델(sonnet), 작은 합성 fixture, 비용은 CLI가 보고한 환산 값(`total_cost_usd`)이며 구독 로그인이면 청구액이 아닌 사용 한도 소모
원본 JSON은 `data/hard-task-comparison/` 아래 회차 폴더에 있고, 회차는 시간 순서

## 과제

| ID | 내용 | 규모 | 기대 등급 |
| --- | --- | --- | --- |
| s1, s2, x1 | 작은 수정, 범위 제한 요청 등 쉬운 과제 | S | 워크플로를 부르지 않아도 되는 수준 |
| m1 | 할인 코드 기능, 말하지 않은 요구 4건 | M | L2 |

## 1회차: 위험 신호와 무관하게 워크플로 경로를 탐

한 과제 한 조건당 1회, 한도에 걸린 45건은 모델이 호출되지 않아 제외, 유효 18건
원본: `data/hard-task-comparison/r1-before-direct-path/`

| 과제 | 직접 처리 | Lite | Full |
| --- | --- | --- | --- |
| l1 숨은 호출처 | 호출처 1곳 파손, 0.058달러 | 파손 0, 0.61달러 | 미실행 |
| m1 암묵 요구 | 누락 1건, 0.055달러 | 누락 0, 0.40달러 | 누락 0, 0.68달러 |
| m2, m3 | 만점 0.04달러 | 만점 0.046달러(워크플로 미호출) | 만점 0.38~0.67달러 |
| s1, s2, x1 | 만점 0.03달러 | 만점 0.02달러 | 해당 없음 |

쉬운 과제의 비용은 워크플로의 효용 근거가 아니며, 불필요하게 워크플로를 부르지 않는지 확인하는 용도로만 기록함

### 이 결과를 보고 고친 것: L2 직접 경로

PM 지침에 L2 직접 경로를 넣어, 위험 신호(L3 기준, 변경 심볼의 외부 사용처, 해석이 둘 이상이거나 암묵 요구 후보, 세 개 이상 파일 또는 기존 테스트 수정, 승인 항목 또는 엄격 모드)가 없으면 위임과 기획 파일 없이 처리하게 함
L3는 직접 경로 대상이 아님을 명시하고, 설계 문서 변경 이력에 데이터를 본 뒤의 보정임을 기록함
이 직접 경로는 이후 제거됨(3회차 변경 참고)

## 2회차: `/subagent` 호출 방식으로 바꾼 뒤 동작 점검

변경: 워크플로가 설치만으로 항상 켜지던 구조를 사용자가 부를 때만 켜지는 `/subagent` 스킬로 바꾸고 L2 직접 경로를 제거
조건별 1회씩의 동작 점검이며 효용 평가가 아니고, 1회차 결과와 합산하지 않음
원본: `data/hard-task-comparison/r2-skill-invocation/`

### 호출 방식

| 요청 | 기대 | 결과 |
| --- | --- | --- |
| 워크플로를 부르지 않은 오탈자 수정 | 평소 Claude가 처리 | 스킬과 위임 없음, Read와 Edit만 사용, 0.04달러 |
| `/subagent` + 요청 | PM 스킬 실행 | 기획 파일 생성, backend, test, qa 위임, 7개 요구 누락 0 (m1, 0.484달러) |
| "서브에이전트 워크플로로 해결해줘: …" | 스킬 자동 호출 | Skill 허용을 준 비대화형 실행에서 `subagent` 호출, 기획 파일과 qa 위임 확인 |
| 같은 말에서 Skill 허용을 주지 않음 | (대화형은 권한 확인) | 스킬 호출이 오류로 반환되어 실행되지 않음, 모델이 이를 보고하고 직접 처리 |

### 어려운 과제 l1 1회

| 조건 | 호출처 파손 | 위임 | 비용 |
| --- | --- | --- | --- |
| Lite | 0 / 호출처 6 | architecture, qa, backend, test, qa | 0.754달러 |
| Full | 0 / 호출처 6 | backend, architecture, backend, test, qa | 0.606달러 |

두 실행 모두 L3 절차(기획 파일, architecture 조사, QA)를 따랐고 직접 수정으로 건너뛴 사례는 없었음
1회차에서 관찰된 L3 우회가 사라졌다고 결론낼 수 없음(조건별 1회)

### 한계

- 반복 1회, 한 모델, 작은 합성 fixture, 비대화형 실행
- 대화형 화면(스킬 실행 허용 창, 신뢰 화면)은 확인하지 못함
- 워크플로가 직접 처리보다 낫다는 비교는 수행하지 않음(직접 처리 기준선은 1회차 측정값)
- 엄격 모드가 메인 세션의 모든 수정에 적용되는 설계는 그대로였음, 워크플로 실행 중으로 한정하는 개선이 남았음

### 해석과 한계

1. 어려운 과제 두 가지에서 direct보다 lite가 놓치는 요구와 깨뜨리는 호출처가 적었음
2. 표본이 과제당 3회이고 direct의 결과가 3회 모두 같아(분산 0) 같은 약점이 반복되는 것으로 보이나, 통계적 유의성은 주장하지 않음
3. 단일 소형 fixture와 단일 모델 결과라 다른 프로젝트와 모델에 일반화할 수 없음
4. 비대화형 실행이라 사용자 확인 단계가 없음
5. 직접 처리가 이미 만점이던 과제는 이 회차에 없어서 "워크플로가 쓸모없는 경우"의 비용 비교는 소규모 fixture의 s1, x1(약 2배) 1회 값뿐이었음
6. 1회차에서 같은 과제 재측정 결과가 갈린 적이 있어 반복 확인이 필요했음

- **실행 이력**: 첫 시도 18회는 Windows에서 npm용 `claude` 실행 파일을 직접 실행하지 못해 모델이 호출되지 않았고(소요 1ms, 지출 없음) 결과에서 전부 제외함, 실행 파일 경로를 고친 뒤 다시 실행함, lite m2 1회차는 그 확인 실행의 결과를 같은 조건이라 그대로 씀
