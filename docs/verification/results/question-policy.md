# 사용자 질문 정책 점검

무엇을 재는가: 요청이 모호할 때 PM이 사용자에게 어떻게 묻는지, 즉 질문을 한 메시지에 모으는지, 세부 사항까지 질문으로 올리지 않는지, 쉬운 말로 선택지와 추천안을 주는지, 같은 질문을 두 번 하지 않는지
배경: 질문 규칙이 PM 지침 여러 곳에 흩어져 있어 언제 어떻게 묻는지 기준이 없었음. 질문 정책 문서(`template/.claude/subagent/questions.md`)를 추가하고 실제 Claude로 확인함
측정일 2026-10-29, Claude Code 2.1.312, 모델 sonnet, 호출당 예산 상한 1달러
도구: `data/question-policy/two-turn-check.cjs`(설치된 시험 프로젝트에서 1턴은 모호한 요청, 2턴은 정해진 답변을 `--resume`으로 이어서 보냄), 원본 JSON은 같은 폴더

## 시험

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | 어려운 과제 평가용 시험 프로젝트(`tools/eval/hard/fixture`), Lite, 권고 모드 설치 |
| 1턴 요청 | `/subagent 주문 합계에 할인이 들어가게 해줘` (할인 방식, 값, 적용 범위가 정해지지 않은 요청) |
| 2턴 답변 | "정률 10퍼센트로 해줘. 나머지는 네가 추천하는 걸로 해줘." |
| 보는 것 | 1턴의 질문 메시지 구조, 정책 문서를 열었는지, 2턴에서 되묻는지 |

- 기준선도 질문을 한 메시지에 모았고 선택지와 추천안을 주었음. 다만 질문 3개 중 "적용 범위"는 앞 질문의 선택지와 겹쳤고 "잘못된 값 처리"는 세부 사항이었음
- 정책 1판과 2판은 정책 문서를 열지 않아 정책이 적용된 결과가 아님. 확인 메시지를 쓰기 직전에 읽으라는 지시가 긴 문장 속에 있어 PM이 따르지 않았음. 같은 PM이 필수로 적힌 `profile.md`, `rule-priority.md`, 계획서 양식은 열었음
- 정책 3판에서만 정책 문서를 열었고, 그때 메시지 구조가 달라졌음. 입력 범위 처리, 수정 범위, 기존 동작 유지 같은 세부 사항을 질문이 아니라 "바꾸라고 하지 않으면 이대로 진행하는 기본값"으로 내렸고 "추천대로 해줘라고만 답하셔도 됩니다"를 안내했음

- 네 실행 모두 새 합계 함수를 만들거나 인자를 추가했을 뿐 실제 주문 흐름의 호출부에 연결하지는 않았고, 연결이 안 됐다는 점을 보고에 적었음. 이 점검의 대상이 아님

## 확인된 점과 고친 것

1. 정책 문서를 별도 파일로 두어도 PM이 열지 않으면 소용이 없음. "읽으라"는 지시를 문장 속에 두면 무시될 수 있고, 접수 단계의 "지금 읽는다" 목록에 두면 열었음(1회)
2. 정책 1판은 질문 수를 줄이지 못했음. 세부 사항까지 질문으로 올리는 문제는 "결정과 기본값을 나눠 보이라"는 구체적인 규칙을 넣고 PM이 그것을 실제로 읽은 뒤에야 달라졌음

## 한계

- 시나리오 1개, 실행마다 1회, 한 모델이라 통계적 증거가 아님. 정책 3판의 구조 변화가 정책 때문인지 실행마다의 변동인지 이 횟수로는 구분할 수 없음
- 정책 3판에서 열었다는 사실은 1회 관찰이며, 항상 여는지는 모름
- 결정 2개 중 일부는 여전히 서로 겹침(할인율을 어디서 가져올지와 어디에 적용할지)
- 질문을 사용자가 읽기 쉬운지는 사람의 판단이며 이 시험은 구조(질문 수, 기본값 목록, 용어)만 셈
- 답변은 정해진 문장으로 보냈고 실제 사용자가 다른 답을 하는 경우, 답이 엇갈리는 경우는 시험하지 않음
- 승인이 필요한 항목(호환성을 깨는 변경 등)을 사용자가 "알아서 해줘"로 넘기는 경우는 시험하지 않음

### 불합격의 성격을 나누면

2. **기준 정의의 문제(다음 회차에서 고쳐야 함)**
